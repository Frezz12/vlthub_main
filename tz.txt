# ?? Music Project Manager — Полное техническое задание (без технической части)

## 1. Общее описание продукта

### 1.1 Название проекта
**MusicProject Manager** (рабочее название) — десктопное приложение для музыкантов, продюсеров и звукорежиссёров, позволяющее сохранять версии музыкальных проектов на сервере, управлять коллаборациями и отслеживать историю изменений по аналогии с Git, но адаптированное для DAW (Digital Audio Workstation).

### 1.2 Цель продукта
Создать удобный инструмент для контроля версий музыкальных проектов, упростить совместную работу над треками и обеспечить надёжное хранение всех этапов создания музыки.

### 1.3 Целевая аудитория
- Музыкальные продюсеры (от начинающих до профессионалов)
- Битмейкеры
- Звукорежиссёры и сведение-мастеринг инженеры
- Вокалисты и инструменталисты, участвующие в записях
- Музыкальные коллективы и лейблы

### 1.4 Платформа
- **Десктопное приложение**: Windows 10/11, macOS 11+
- **Кроссплатформенность**: Единый код для обеих ОС
- **Стиль**: Минималистичный, в духе Apple (чистые линии, много воздуха, прозрачность, плавные анимации)

## 2. Функциональные требования

### 2.1 Авторизация и управление профилем

#### 2.1.1 Регистрация
- Регистрация по email
- Подтверждение email через ссылку в письме
- Поля регистрации:
  - Email
  - Пароль (минимум 8 символов, хотя бы одна цифра)
  - Никнейм артиста (отображаемое имя)
  - Уникальный юзернейм (латиница, цифры, точка, без пробелов)
- После регистрации — автоматический вход

#### 2.1.2 Вход в аккаунт
- Вход по email + пароль
- Кнопка "Забыли пароль?" — восстановление через email
- Запоминать сессию (функция "Оставаться в системе")

#### 2.1.3 Профиль пользователя
- **Фото профиля**: загрузка изображения (JPG, PNG, до 5 MB), обрезка под круг
- **Никнейм артиста**: можно менять
- **Юзернейм**: можно менять, но с проверкой уникальности
- **Биография**: текстовое поле (до 500 символов)
- **Социальные сети**: ссылки на Instagram, SoundCloud, YouTube (опционально)
- **Статистика**: количество проектов, версий, коллабораций
- **Настройки приватности**: профиль может быть публичным или только по ссылке

#### 2.1.4 Выход из аккаунта
- Кнопка выхода в настройках
- При выходе — очистка локального кэша

### 2.2 Работа с проектами

#### 2.2.1 Создание проекта
Пользователь может создать проект двумя способами:

**Способ 1 — Добавление существующего DAW проекта:**
- Нажать кнопку "Добавить проект"
- Выбрать папку с проектом DAW (Logic Pro, Ableton, FL Studio, Cubase, REAPER)
- Приложение автоматически определяет DAW и извлекает метаданные (BPM, тональность, если возможно)
- Заполнить информацию о треке (см. п. 2.3)

**Способ 2 — Создание нового проекта в приложении:**
- Нажать "Создать проект"
- Указать название
- Позже привязать к нему папку проекта DAW

#### 2.2.2 Информация о проекте (карточка трека)
Для каждого проекта хранится следующая информация:

| Поле | Тип | Обязательное | Пояснение |
|------|-----|--------------|-----------|
| Название трека | Текст | Да | Например, "Summer Vibes" |
| Артист(ы) | Список пользователей | Да | Основной исполнитель + приглашённые |
| Битмейкер | Список пользователей | Нет | Кто сделал бит |
| BPM | Число (60-200) | Нет | Темп трека |
| Тональность | Строка (A#m, Cmaj) | Нет | Музыкальная тональность |
| Sample Rate | Выбор (44.1/48/96 кГц) | Нет | Частота дискретизации |
| Описание | Текст (до 2000 символов) | Нет | О чём трек, вдохновение и т.д. |
| Обложка | Изображение | Нет | Можно загрузить обложку трека |
| Теги | Список строк | Нет | #hiphop #edm #lofi и т.д. |

#### 2.2.3 Список проектов
Главный экран приложения показывает:
- Список всех проектов пользователя (включая фиты, где он участник)
- Карточка проекта содержит:
  - Обложку (или заглушку)
  - Название трека
  - Никнейм артиста
  - BPM и тональность (если указаны)
  - Количество версий
  - Дата последнего изменения
  - Значок DAW (Logic, Ableton и т.д.)
- Поиск по названию, артистам, тегам
- Фильтрация: "Мои проекты", "Фиты", "Доступные мне", "Архив"
- Сортировка: по дате, по названию, по количеству версий

#### 2.2.4 Редактирование проекта
- Изменять информацию о треке можно в любой момент
- История изменений метаданных НЕ хранится (только версии проекта)

### 2.3 Система версий (Git-подобная)

#### 2.3.1 Создание новой версии
Процесс сохранения версии:

1. Пользователь открывает карточку проекта
2. Нажимает кнопку **"Сохранить новую версию"**
3. Открывается модальное окно с полями:
   - **Название версии** (по умолчанию: "Версия 1.0.0 — дата время")
   - **Описание изменений** (что сделано нового, что исправлено)
   - **Загрузить аудио-превью** (WAV или MP3, опционально)
   - **Чекбокс**: "Сделать эту версию текущей"
4. Приложение:
   - Копирует папку проекта во временную папку
   - Очищает от мусорных файлов (кэш, временные файлы)
   - Архивирует в ZIP
   - Отображает прогресс загрузки
   - Отправляет на сервер
5. После загрузки — версия отображается в истории

#### 2.3.2 История версий
- Временная шкала всех версий проекта (похожа на GitHub Timeline)
- Каждая версия отображается как карточка с:
  - Номером версии (автоинкремент)
  - Названием версии
  - Датой создания
  - Кем создана (никнейм)
  - Описанием изменений
  - Наличием аудио-превью (значок ??)
  - Кнопками: **Скачать**, **Прослушать**, **Сделать текущей**
- Возможность развернуть версию и увидеть:
  - Полное описание
  - Список файлов в архиве (только имена)
  - Размер архива

#### 2.3.3 Управление версиями
- **Скачать версию**: получить ZIP-архив проекта
- **Удалить версию**: только владелец проекта (с подтверждением)
- **Сравнение версий**: выделить две версии и увидеть, какие файлы изменились (имена и размеры)
- **Комментарии к версии**: участники проекта могут оставлять текстовые комментарии к конкретной версии

#### 2.3.4 Аудио-превью
- Пользователь может загрузить WAV или MP3 при сохранении версии
- Формат превью: конвертируется в MP3 192 kbps для быстрой загрузки
- Превью привязывается к конкретной версии
- Прослушивание прямо в приложении со встроенным плеером:
  - Play/Pause
  - Progress bar
  - Отображение времени
  - Визуализация (простая спектрограмма)
- Можно загрузить несколько превью для одной версии (например, полная версия и инструментал)

### 2.4 Коллаборации и фиты

#### 2.4.1 Добавление фит-артиста
При создании или редактировании проекта:

1. Нажать "Добавить артиста"
2. Выбрать тип:
   - **Зарегистрированный пользователь** (поиск по юзернейму или email)
   - **Внешний артист** (просто ввести имя)
3. Указать роль:
   - Вокалист
   - Продюсер
   - Автор текста
   - Инструменталист
   - Сведение
   - Мастеринг
4. Если выбран зарегистрированный пользователь:
   - Отправляется уведомление (в приложении и на email)
   - Артист может принять или отклонить фит
   - После принятия — проект появляется в его списке "Фиты"

#### 2.4.2 Управление фитами
- Владелец проекта может добавить/удалить фит-артистов в любой момент
- Удалённый фит-артист теряет доступ к проекту
- Фит-артист может выйти из фита самостоятельно (проект остаётся у владельца)

#### 2.4.3 Общий доступ (Sharing)
Владелец проекта может поделиться доступом с другими пользователями:

**Роли доступа:**

| Роль | Возможности |
|------|-------------|
| **Владелец** | Полный контроль: удаление проекта, передача владения, управление доступом |
| **Редактор** | Сохранять новые версии, загружать превью, редактировать метаданные, оставлять комментарии |
| **Комментатор** | Только просматривать версии, слушать превью, оставлять комментарии |
| **Зритель** | Только просматривать историю версий и слушать превью |

**Способы поделиться:**
- **По email**: ввести email пользователя, выбрать роль, отправить приглашение
- **По ссылке**: сгенерировать публичную ссылку с ограниченным доступом (гостевая ссылка с паролем, истекает через N дней)

## 3. Нефункциональные требования

### 3.1 Производительность
- Запуск приложения: не более 3 секунд
- Открытие списка проектов: менее 1 секунды
- Архивирование проекта 1 GB: не более 30 секунд (на современном ПК)
- Загрузка на сервер на скорости 100 Mbps: 1 GB за ~2 минуты
- Плеер аудио-превью: задержка воспроизведения менее 0.5 секунды

### 3.2 Надёжность
- При обрыве интернета — дозагрузка чанков с места остановки
- Автоматическое восстановление сессии после перезапуска
- Проверка целостности архива (SHA256) после загрузки

### 3.3 Безопасность
- Пароли хешируются (bcrypt)
- JWT токены с ограниченным сроком жизни (15 минут, refresh токен 7 дней)
- Все запросы к API через HTTPS
- Загрузка файлов только авторизованных пользователей
- Подписанные URL для скачивания (действуют 1 час)

### 3.4 UX/UI требования (стиль Apple)

- **Фон**: #F5F5F7 (светлая тема), #1C1C1E (тёмная тема)

- **Вторичный текст**: #86868B
- **Границы**: #E5E5EA (светлая), #38383A (тёмная)

#### 3.4.2 Типографика
- Системный шрифт Apple: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto
- Заголовки: SemiBold 20-28pt
- Основной текст: Regular 13-15pt
- Мелкий текст: Regular 11-12pt

#### 3.4.3 Компоненты
- **Кнопки**: скруглённые (8px), эффект нажатия (анимация), прозрачные или залитые
- **Карточки проектов**: фон с размытием (backdrop-filter: blur(20px)), тень 0 2px 8px rgba(0,0,0,0.05)

- **Прогресс-бары**: тонкие (2px), акцентный цвет с анимацией
- **Иконки**: SF Symbols или Feather Icons (тонкие, минималистичные)

#### 3.4.4 Анимации
- Плавное появление элементов (fade in, 200ms)
- Пружинные эффекты при переключении вкладок
- Пульсация кнопки загрузки во время процесса

## 4. Сценарии использования (User Stories)

### 4.1 Сохранение первой версии проекта
1. Пользователь открывает приложение, авторизуется
2. Нажимает "Добавить проект", выбирает папку Logic Pro проекта
3. Приложение находит проект, показывает "Новый трек: Untitled"
4. Пользователь заполняет: название "Summer Vibes", BPM 128, тональность Cm
5. Нажимает "Сохранить версию"
6. Пишет описание: "Первый набросок, драм-партия готова"
7. Нажимает "Сохранить"
8. Приложение архивирует и загружает проект
9. Появляется уведомление: "Версия 1.0 сохранена"

### 4.2 Добавление фит-артиста
1. Продюсер создал проект, хочет добавить вокалистку
2. Нажимает "Добавить артиста", ищет "jazz_singer"
3. Находит профиль, выбирает роль "Вокалист", отправляет приглашение
4. Вокалистка получает email: "DJ Smith приглашает вас в проект Summer Vibes"
5. Заходит в приложение, принимает приглашение
6. Проект появляется в её списке "Коллаборации"
7. Она может слушать превью версий и скачивать проект

### 4.3 Совместная работа над версией
1. Продюсер сохраняет версию 1.2 с вокалом
2. Вокалистка получает уведомление: "Новая версия проекта"
3. Слушает превью в приложении
4. Оставляет комментарий: "В припеве нужно поправить тайминг"
5. Продюсер видит комментарий, сохраняет версию 1.3 с исправлениями

### 4.4 Восстановление старой версии
1. Продюсер случайно испортил проект в DAW
2. Открывает приложение, находит проект
3. Переходит в "История версий"
4. Находит версию 1.5 от прошлой недели
5. Нажимает "Скачать"
6. Распаковывает архив и открывает в Logic Pro

7. Auth Flow
Register:
  Client ? POST /auth/register
  Server ? hash password, create user, send confirmation email
  Server ? return access_token + refresh_token + user
  Client ? store tokens (memory + httpOnly cookie for refresh)
Login:
  Client ? POST /auth/login
  Server ? verify credentials, return tokens
  Client ? redirect to dashboard
Token Refresh:
  Client ? interceptor detects 401
  Client ? POST /auth/refresh (sends refresh_token in cookie/body)
  Server ? verify refresh token, issue new access_token
  Client ? retry original request
Logout:
  Client ? POST /auth/logout
  Server ? delete refresh token from DB
  Client ? clear local tokens ? redirect to login
8. File Upload/Download Flow
Upload (save version):
  1. User clicks "Save version" ? modal opens
  2. User fills metadata, optionally selects audio preview
  3. Tauri (Rust):
     a. Copies project folder to temp
     b. Cleans cache/temp files
     c. Archives to ZIP
     d. Calculates SHA256
  4. Nuxt sends POST /projects/:id/versions (metadata)
     ? Server creates Version record (status: 'pending')
     ? Returns upload_id + signed upload URL
  5. Tauri (Rust): uploads file in 8MB chunks
     ? Each chunk: PUT with Content-Range header
     ? Reports progress via Tauri events ? UI progress bar
  6. On completion:
     ? Server verifies SHA256
     ? Background task (RQ high): extracts file listing, updates size
     ? Server marks version as 'completed'
  7. UI: toast "Version X saved"
Download:
  1. User clicks "Download version"
  2. Client ? POST /versions/:verId/download
